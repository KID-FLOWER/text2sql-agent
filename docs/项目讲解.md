# 项目讲解（面试速查）

> 这份文档的目标：让你在 10.27 面试时，**不看稿也能把这张图讲出来**。

---

## 1. 一句话概括

用户问一句中文 → **模型不直接猜答案**，而是通过三把"工具"去看数据库 → 每拿到一次结果就再决定下一步 → 直到它觉得够了，用中文回答。

区别就在这：普通 ChatGPT 是"闭卷考试"，这个 Agent 是"开卷 + 允许翻书"。

---

## 2. 一次提问的完整数据流

以「张老师带的班里，编程成绩前三名是谁？」为例：

```
用户：张老师带的班里，编程成绩前三名是谁？
        │
        ▼
[第1轮] 发给模型 = system prompt + 这个问题 + 3 个工具的 JSON Schema
        │
        ├─ 模型：我需要先看看有哪些表 → 返回 tool_calls=[list_tables]
        │      （注意：这是模型自己决定的，不是我写死的 if-else）
        ▼
   我们执行 list_tables() → {"tables":["classes","scores","students","teachers"], ...}
        │
        ▼
[第2轮] messages 里追加 {role:"tool", tool_call_id:..., content:上面的结果}
        ├─ 模型：classes 里 teacher_id 指向哪张表？→ tool_calls=[get_table_schema("classes")]
        ▼
   返回列定义 + 外键 + 2 行样例
        │
        ▼
[第3轮] 模型：现在可以写 JOIN 了 → tool_calls=[execute_sql_query("SELECT ...")]
        ▼
   返回 {"columns":["name","class_name","score"], "rows":[["韩八","三班",94], ...]}
        │
        ▼
[第4轮] 模型不再要工具，content = "前三名是：韩八 94、朱十 92、吕四 89……"
```

**核心**：`messages` 这个列表每轮都在变长，模型自己不记事，全靠每轮把整段历史重发一遍。

---

## 3. 每个文件在干什么

| 文件 | 一句话 | 为什么这么设计 |
|---|---|---|
| `init_db.py` | 老师给的建库脚本 | **原样保留**，一个字不改，避免"改了数据导致结果对不上"的嫌疑 |
| `tools.py` | 三个工具 + 三份 JSON Schema | 工具和说明书放一起，模型看到的描述和真实行为不会脱节 |
| `agent_loop.py` | while 循环 + System Prompt | 引擎，真正的"Agent"就在这里 |
| `test_tools.py` | 工具层单元测试（22 项） | 先证明工具没 bug，再去怀疑模型 |
| `test_queries.py` | 跑题目指定的 5 个问题 | 产出实验记录要的日志 |
| `verify_api.py` | 最小连通性验证 | 分层排错：先证明网络和 Key 通，再写复杂逻辑 |

## 4. 五个必答问题（面试高频）

### Q1：为什么不把表结构直接塞进 prompt？

表少的时候确实可以。但表一多就会撑爆上下文，而且模型仍然不知道数据里存的是"三班"还是"3班"。探索式的好处是**通用**：换一个库、加一张表，代码不用改。代价是多花几轮 token——这是拿成本换通用性。

### Q2：function calling 里，函数到底是谁执行的？

**模型只输出一段 JSON**：`{"name":"execute_sql_query","arguments":"{\"sql\":\"SELECT...\"}"}`。它**碰不到**你的数据库、碰不到你的文件系统。真正执行的是 `tools.py` 里的 `dispatch()`，执行完把结果字符串塞回 `messages`。

> 这题答错最致命。模型的全部能力就是"写字"，动手的永远是你的代码。

### Q3：工具报错，为什么返回字符串而不是抛异常？

抛异常会直接打断循环，模型永远看不到错在哪，下一轮还是原样再发一次。返回错误原文，模型就能读到 `no such column: namee`，下一轮改成 `name`。**所谓 Self-Correction，不是模型变聪明了，是你给了它一条能读到错误的反馈通道。**

### Q4：三道安全锁分别防什么？

| 锁 | 防什么 |
|---|---|
| ① 语句校验：只放行 SELECT / WITH 单条语句 | 防模型被诱导写出 `DROP TABLE` |
| ② `mode=ro` 只读打开数据库 | 防"正则被绕过"——就算校验漏了，SQLite 也拒绝写入 |
| ③ `PRAGMA query_only = ON` | 防连接复用时的意外写入 |

这是**纵深防御**：任何一层被绕过，还有下一层。

### Q5：MAX_STEPS 为什么必须有？设小了会怎样？

模型可能陷入"查了不对 → 再查 → 还不对"的循环，烧钱且卡死。步数上限是止损；用完之后的兜底是**摘掉 tools 参数**，逼它基于已有信息作答（而不是直接报错）。

设小了（比如 3）：第 3 题的 JOIN 需要"列表 → 看结构 → 执行"至少 3 步，没有余量给自我修正。
设大了（比如 30）：死循环时烧的钱就多了。**8 步是"够用且可控"的折中。**

## 5. 数据里的三个坑（能主动说出来就赢了）

1. **张老师带两个班（三班 + 四班）**。只查一个班，"前三名"会算错——第三名会变成三班的 85 分，而真实第三名是四班的吕四 89 分。
2. **缺考不是"没有记录"，而是记录少于 5 门**。学生表里王明、卫五都在，只是各自少一门成绩。所以要用 `LEFT JOIN` + `HAVING COUNT < 5`，用 `INNER JOIN` 会把他们直接漏掉。
3. **"哪个班平均分最高"取决于口径**：
   - 按每条成绩记录求平均 → 一班 78.26，三班 78.20
   - 先算每个学生的平均、再按班平均 → 三班 78.20 **反超**一班 78.17

   因为王明缺考编程，一班只有 34 条成绩，两种算法权重不同。**能主动指出这一点，比答对一个数字更有价值。**

## 6. 报错速查

| 报错 | 原因 | 处理 |
|---|---|---|
| `[配置缺失]` | `.env` 还是占位符 | 填真实 Key |
| `AuthenticationError` 401 | Key 错 / 有空格 | 重新复制，检查末尾空格 |
| `InsufficientBalance` 402 | 余额不足 | 充值 |
| `APIConnectionError` | 网络/代理 | 换网络 |
| `ModuleNotFoundError` | 没激活 venv | `.venv\Scripts\activate` |
| `no such table: xxx` | 表名错 | 先 `list_tables` |
| `no such column: xxx` | 列名错 | 先 `get_table_schema` |
